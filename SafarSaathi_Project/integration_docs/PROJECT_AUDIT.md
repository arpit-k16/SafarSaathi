# SafarSaathi repository audit — 2026-10-29

## Scope and preservation
The application root is `SafarSaathi_Project/`, below the workspace. The sibling `SafarSaathi_Datasets/` is the immutable raw collection. Neither directory is a Git checkout: `git status --short` reports no repository. Pre-existing files and changes therefore cannot be compared with a Git commit; no reset or cleanup is appropriate. `frontend_sha256_original.json` records all 475 frontend files (including hidden files) before implementation. Release copies and trash directories are historical material, not the active application. `repository_inventory.json` records paths and sizes outside caches/dependencies at audit time.

## Existing architecture
- React 19.3.1, React DOM, Vite 8.3.4, plain JSX and CSS. Scripts: `dev: vite`, `build: vite build`, `lint: oxlint`, `preview: vite preview`. Default Vite port 5173; current config only installs the React plugin. Node 24.17.0 is installed.
- Navigation is React `activeTab` state in App.jsx, with sidebar identifiers; no URL router. Landing, overview, twin, disaster and what-if pages are dedicated components; all other tabs use AuxiliaryView with fixed KPI/text content.
- No fetch, axios, XMLHttpRequest, API URL environment variable, proxy, injected-data hook or API client exists in current frontend source/config. Components contain fixed telemetry, illustrative dispatch toasts and, for what-if, locally weighted stress/delay arithmetic. Backend cannot cause these components to read HTTP responses. The original frontend remains read-only.
- Existing Python backend: stdlib BaseHTTPRequestHandler/ThreadingHTTPServer in `src/safarsaathi_ml/http_api.py`, bound to 127.0.0.1, CLI entry `python -m safarsaathi_ml.cli serve`. Reuse it; adding FastAPI or a database is unnecessary.
- Original GET routes: /health, /models, /models/{id}, /capabilities, /system/summary, /stress/indicator-metadata. POST: /reviews/classify, /tourism/forecast, /tourism/monthly-forecast, /disaster/predict, /flood/segment, /stress/predict, /stress/indicators, /disaster/cyclone-count, /environment/pm25-forecast.
- Runtime modules separate registry, persistence, trusted artifact loading, classification, annual/monthly/scoped forecasting, flood segmentation and historical indicators. Registry pins artifact paths/checksums; models are not trained on requests. Artifact loading currently deserializes repeatedly.

## Models and data
Six active registered pipelines exist: `nlp-20261024T182952Z`, `tourism_demand_forecaster`, `tourism_monthly_fta_forecaster`, `flood_segmentation_model`, `north_indian_cyclone_count_forecaster`, `india_pm25_exposure_forecaster`. Two older NLP artifacts also remain on disk but are not active registry entries. Metadata, feature/evaluation JSON, integrity manifest and model cards exist. Actual loading and valid inference must be checked; persisted files alone are insufficient evidence.

- Annual national arrivals: 25 observations 1995–2019; World Bank ST.INT.ARVL. Existing load_arrivals validation and forecasting pipeline.
- Monthly national foreign tourist arrivals: derived CSV/provenance under data/processed/tourism_monthly_fta/20261025, 72 rows 2019–2024. Existing PDF-extraction/build scripts; a different target from annual international arrivals.
- Cyclone: 540 NI-basin monthly archive counts 1980–2024; PM2.5: 34 national modeled annual values 1990–2023. Source and derived manifests exist under data/external and data/processed/india_scope_20261025.
- Historical indicator snapshot: outputs/indicators/india_environment_tourism with integrity pin, source flags, formulas, null missingness, national and State/UT coverage.
- Raw collection categories: tourism_india (PDF/DOC), weather_nasa_power (reanalysis JSON), osm_india (PBF), disaster_undrr (taxonomy JSON), sentinel1 (SAR TIFF and metadata), sentinel2 (JP2 and metadata), reviews (CSV/JSON and dataset cards), worldbank_un_tourism (JSON/ZIP). DATA_MANIFEST.csv carries per-file attribution/coverage/license, not a live-connection guarantee.
- Additional project raw_v2: named-location NASA POWER JSON (query coordinates differ slightly from actual grid-point coordinates), OSM regional files, tourism PDFs. Separate STURM benchmark ZIP, Sentinel metadata CSV and verification records exist under data/external/sturm_flood/12748983. Raw local Sentinel scenes have no verified conversion into the STURM preprocessed input format; do not wire them directly to segmentation.
- `notebooks/ml_readiness_review.ipynb` is an inspection companion; deployable inference lives in Python modules. `dashboard/index.html` embeds older analytical results; it is not the current React frontend or a validated live service.

## Tests, scripts and runtime
Existing pytest tests cover registry integrity, artifact reload, forecast replay, HTTP validation, flood input, missing artifacts and indicator provenance. One HTTP test invokes `frontend/tests/api.test.js`, which is absent in this frontend; this is a stale test assumption, not evidence of integration. Source fetch/build/release scripts exist; none should be run against raw data as part of serving. configs/run_config.json configures offline audit/training, not frontend integration. No database, cloud service, Docker deployment or live sensor connection is configured.

Installed: Python 3.14.6, numpy 2.4.6, pandas 2.3.3, scikit-learn 1.9.1, joblib 1.6.0, pytest 8.4.2, tifffile 2026.10.15. requirements.txt already supplies these libraries; reuse it. Existing README launch instructions incorrectly claim a combined npm launcher, port 3000, npm test and VITE_SAFARSAATHI_API_URL; actual package/config/source disagree. The integration runbook must supersede these claims.

## Gaps and risks
No validated destination stress labels, full multi-hazard warning model, real-time GIS/occupancy/capacity, deployment-cost/benefit objective, server-side simulation/optimization or report generator exists. OSM files alone do not establish routable operational layers. Model cards document historical scope, experimental precision and license restrictions (including noncommercial review corpora). Avoid exposing raw review text, private absolute paths or credentials. CORS must remain restricted to actual local origins. API responses currently expose full metadata in places; sanitize paths before publication. Logs currently suppress all HTTP request logging. External Tailwind/fonts in index.html require connectivity; no frontend build/install should be run inside the protected directory. No frontend page can be honestly labeled CONNECTED until the user separately authorizes client integration.
